# 대출 장부 봇 설계

사용자가 대출 명단과 상환 내역을 입력하면, 봇이 상환 일정 생성, 상태 판단, 연체 처리, 입력 로그 기록을 자동으로 하는 디스코드 봇이다.

- 테스트용 가상 화폐를 전제로 하며, 현금 거래에는 사용하지 않는다.
- 봇은 잔액을 보관하지 않는다. 지갑과 화폐 지급 기능은 없고, 대출 장부만 관리한다.

## 1. 역할

| 대상 | 할 수 있는 일 |
|---|---|
| 관리자 역할 (0순위) | 설정 변경과 일반 역할의 모든 기능 |
| 일반 역할 (1순위) | 대출 등록, 상환 입력, 목록 조회, 상세 조회, 대출 이력 조회 |
| 역할 없음 | 사용 불가 |

권한은 봇이 명령어 실행자의 디스코드 서버 역할 이름을 읽어 판단하고, 명령어 클래스의 어노테이션으로 지정한다. 순위 숫자가 낮을수록 권한이 높으며, 높은 순위는 낮은 순위의 명령어를 모두 사용할 수 있다. 아래 표의 `모두`는 일반 역할 이상을 뜻한다. 코드 구조는 [코드 설계](loan-bot-code-design.md)를 따른다.

## 2. 명령어

| 명령어 | 권한 | 입력값 | 결과 |
|---|---|---|---|
| `/대출등록` | 모두 | 고유번호, 유저명, 금액, 상환방식 | 대출 생성, 상환 일정 안내, 로그 기록 |
| `/대출상환` | 모두 | 고유번호, 유저명, 상환금액 | 상환 반영, 처리 결과와 현재 상태 안내, 로그 기록 |
| `/목록` | 모두 | 없음 | 상태별로 묶은 대출 목록 표시 |
| `/상세조회` | 모두 | 고유번호 | 회차별 납부 금액과 납부일, 이번에 갚을 금액, 남은 금액, 연체액 표시 |
| `/대출이력` | 모두 | 고유번호 | 해당 고유번호의 대출 이력을 최신순으로 표시 |
| `/설정 보기` | 관리자 | 없음 | 현재 설정값 표시 |
| `/설정 변경` | 관리자 | 항목, 값 | 금리, 연체 이자율 등 설정값 변경 |

상환방식은 `원리금균등`, `원금균등`, `만기일시` 중에서 선택한다.

## 3. 설정값

등록할 때 입력하지 않는 값은 관리자 설정에서 가져온다. 아래 기본값은 테스트용 초기값이다.

| 설정 | 기본값 | 허용 범위 | 설명 |
|---|---|---|---|
| 회차당 금리 | 1% | 0~30% | 정상 이자 계산에 사용 |
| 회차당 연체 이자율 | 1% | 0~30% | 연체 금액에 추가 |
| 상환 회차 | 12회 | 1~60회 | 총 납부 횟수 |
| 납부 주기 | 1일 | 1분~12개월 | 테스트할 때는 분 단위로 설정 |
| 납부 임박 기준 | 24시간 | 1분~30일 | 납부일까지 남은 시간 |
| 최대 대출 금액 | 100,000,000 | 1~1,000,000,000,000 | 등록 금액 상한 |
| 로그 채널 | 없음 | 서버의 텍스트 채널 | 등록과 상환 로그를 보낼 채널 |

- 금리, 회차, 납부 주기는 등록 시점의 값을 대출에 저장한다. 설정을 바꿔도 이미 등록된 대출의 일정은 바뀌지 않는다.
- 연체 이자율은 변경 이후 새로 발생하는 연체 이자부터 적용한다.

## 4. 입력 검증

| 대상 | 규칙 | 실패 시 |
|---|---|---|
| 금액 | 1 이상의 정수, 최대 대출 금액 이하 | 등록 거부, 허용 범위 안내 |
| 설정값 | 3번 표의 허용 범위 안 | 변경 거부, 허용 범위 안내 |
| 대출 수 | 같은 고유번호로 완납 전 대출이 있으면 불가 | 등록 거부, 이미 대출 중이라고 안내 |
| 상환금액 | 1 이상의 정수, 남은 총액 이하 | 상환 거부, 남은 총액 안내 |
| 고유번호와 유저명 | 등록된 정보와 일치 | 상환 거부, 입력 확인 안내 |

완납한 고유번호는 새로 대출을 등록할 수 있다.

## 5. 상환 일정 계산

금액은 원 단위 정수로 저장한다. 회차별 이자는 반올림하고, 끝전은 마지막 회차에서 맞춰 원금 합계가 대출 금액과 정확히 일치하게 한다. 금리가 0%이면 이자 없이 원금만 나눈다.

| 방식 | 계산 |
|---|---|
| 원리금균등 | 매 회차 `원금 × r × (1+r)^n ÷ ((1+r)^n − 1)`을 납부 |
| 원금균등 | 매 회차 `원금 ÷ 회차 + 남은 원금 × 금리`를 납부 |
| 만기일시 | 매 회차 `원금 × 금리`를 납부하고 마지막 회차에 원금까지 납부 |

`r`은 회차당 금리, `n`은 총 회차다.

### 예시: 1,000,000원, 회차당 1%, 3회

| 회차 | 원리금균등 | 원금균등 | 만기일시 |
|---|---:|---:|---:|
| 1 | 340,022 | 343,333 | 10,000 |
| 2 | 340,022 | 340,000 | 10,000 |
| 3 | 340,023 | 336,667 | 1,010,000 |

## 6. 상환 처리

입력한 금액은 다음 순서로 반영한다.

1. 가장 오래된 회차의 연체 이자
2. 가장 오래된 회차의 미납 금액
3. 다음 회차 금액

- 한 회차 금액보다 적게 내면 일부 납부로 기록하고, 해당 회차는 미납으로 남는다.
- 회차 금액보다 많이 내면 남는 금액을 다음 회차에 반영한다.
- 조기 상환해도 이후 회차의 이자를 다시 계산하지 않는다. 테스트용 단순화 규칙이다.
- 남은 금액이 0이 되면 상태를 완납으로 바꾼다.

## 7. 상태 판단

봇이 납부일과 납부 내역을 기준으로 자동으로 판단한다. 위에서부터 먼저 맞는 상태를 적용한다.

| 상태 | 조건 |
|---|---|
| 🔵 완납 | 남은 금액 없음 |
| 🔴 연체 | 납부일이 지났는데 미납 금액이 남은 회차가 있음 |
| 🟡 납부 임박 | 다음 납부일까지 남은 시간이 임박 기준 이하 |
| 🟢 정상 | 그 외 |

## 8. 연체 자동 처리

- 스케줄러가 1분마다 미완료 대출을 확인한다.
- 납부일이 지난 미납 회차에 납부 주기가 한 번 지날 때마다 `미납 금액 × 연체 이자율`을 추가한다. 연체 이자에는 다시 이자를 붙이지 않는다.
- 같은 기간에 이자가 두 번 붙지 않도록 회차별 마지막 연체 이자 계산 시각을 저장한다.
- 봇이 꺼져 있던 기간은 재시작 후 지나간 주기만큼 한 번에 계산한다.
- 시간대는 `Asia/Seoul`을 사용한다.

## 9. 대출 이력과 입력 로그

### 대출 이력

대출 하나의 변화 과정을 기록한다. 완납 후 재대출해도 이전 이력은 지우지 않는다.

- 기록 대상: 대출 등록, 상환 반영, 연체 시작, 연체 이자 추가, 완납
- 기록 내용: 대출번호, 고유번호, 유저명, 이력 종류, 금액, 처리 후 남은 금액, 발생 시각
- 입력자가 없는 연체 이력은 봇이 자동으로 기록한다.
- `/대출이력`은 최신 10건을 먼저 표시한다.

### 입력 로그

모든 사용자가 등록과 상환을 입력할 수 있으므로 누가 무엇을 입력했는지 기록한다.

- 기록 대상: `/대출등록`, `/대출상환`의 성공과 거부
- 기록 내용: 처리 시각, 입력한 디스코드 사용자, 명령어, 입력값, 처리 결과
- 저장 위치: DB에 항상 저장하고, 로그 채널이 설정되어 있으면 해당 채널에도 보낸다.
- 로그 채널 전송에 실패해도 등록과 상환 처리는 유지하고, DB 로그는 남긴다.

## 11. 저장 구조

코드를 먼저 만들 때는 메모리 저장소를 사용하고, 이후 Firebase 무료 요금제의 Firestore로 교체한다. 메모리 저장소는 재시작하면 데이터가 사라진다. 아래 항목은 논리 구조이며, Firestore 문서 구조는 [코드 설계](loan-bot-code-design.md)를 따른다.

| 테이블 | 주요 항목 |
|---|---|
| `loan` | 고유번호, 유저명, 원금, 방식, 금리, 회차, 납부 주기, 등록일, 완료일 |
| `installment` | 대출, 회차, 납부일, 원금, 이자, 납부액, 연체 이자, 마지막 연체 계산 시각 |
| `repayment` | 대출, 상환금액, 입력한 사용자, 처리 시각 |
| `loan_setting` | 설정 항목, 값, 수정자, 수정 시각 |
| `loan_log` | 입력한 사용자, 명령어, 입력값, 처리 결과, 처리 시각 |
| `loan_event` | 대출번호, 고유번호, 유저명, 이력 종류, 금액, 처리 후 남은 금액, 발생 시각 |

납부 임박과 연체 표시는 조회할 때 계산한다. 상환과 연체 처리는 저장소의 원자적 갱신으로 묶어 중복 반영을 막는다.

## 12. 이번 범위에서 제외

지갑, 화폐 지급, 신용 점수, 대출 심사, 유저 간 대출, 강제 회수, 주식 연동, 등록과 상환 취소

## 13. 확인할 사항

- `고유번호`는 은행에서 정한 고객 번호로 가정한다. 디스코드 사용자 ID를 쓰려면 입력 형식을 바꾼다.
- 등록 명령어에 금리와 기간이 없으므로 관리자 설정값을 사용한다. 대출마다 다르게 정하려면 등록 입력값을 추가한다.
- `/목록`과 `/상세조회`는 모든 사용자에게 이름과 금액을 공개한다.
- 모든 사용자가 등록과 상환을 입력할 수 있어 잘못된 입력이 생길 수 있으며, 취소 기능은 없으므로 로그로 확인한다.
